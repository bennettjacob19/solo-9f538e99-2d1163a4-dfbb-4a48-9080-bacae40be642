# 遥测 UDP 代理（接收器 A/B 切换 + 上游端口池演示）

遥测终端经 UDP 代理把短报文发给接收器，值班员在网页上切换接收器 A/B，
已建立的会话不受影响，回包不会送错设备。网页还可演示上游端口池被同机
进程占用时的建连行为，并用真实 UDP 试传核对两端端口。

## 组成

| 组件 | 说明 |
|---|---|
| `proxy/` | asyncio UDP 代理 + Flask 操作网页 + SQLite 持久化 + 端口池管理 |
| `proxy/port_occupier.py` | 独立演示进程：与代理同一网络命名空间，真实占用/释放池内端口 |
| `receiver/` | 本地接收器，原样回显报文，可延迟回包，按试传标识回报实收源端口 |
| `docker-compose.yml` | 一键启动代理 + 接收器 A + 接收器 B |
| `scripts/verify_local.py` | 无 Docker 环境下的端到端行为验证 |

## 启动

```bash
docker compose up --build
```

- 操作网页：http://localhost:8080
- 遥测终端发送地址：`UDP <宿主机>:9000`

## 行为规则

- **会话**：按客户端 `IP:端口` 建立，空闲 5 秒（`SESSION_IDLE_TIMEOUT`）无收发即过期。
- **建会话时固定接收器**：会话期间的一切报文都发往建会话那一刻的目标接收器；
  网页切换 A/B 只影响之后新建的会话，旧会话继续走原接收器直到过期。
- **原样透传**：普通报文与回包内容不做任何修改。
- **回包不错投**：每个会话使用一条独立的、已 connect 到其接收器的上游 UDP
  套接字（独立本地端口），只有该会话对应接收器的回包会被送回该客户端。
- **上游端口池搜索**：建连时在池内（`UPSTREAM_PORT_MIN/MAX`）搜索可绑定端口——
  - 同一轮每个端口最多尝试绑定一次；
  - 遇到绑定冲突（如同机进程占住连续几个端口）继续找下一个，
    **池内确实无可用端口才报"端口池用尽"**；地址解析失败等其它原因单独上报；
  - 并行建连各自预留不同端口，不得共用；
  - 因其他建连预留而跳过的端口，若在本轮结束前释放且不在冷却期，也会再检查；
  - 搜索期间已有会话照常收发和过期，释放的会话端口照常冷却；
  - 绑定失败不进黑名单：外部进程释放端口后，新会话无需重启即可使用。
- **迟到回包**：会话过期即关闭其上游端口，端口进入冷却期
  （`UPSTREAM_PORT_COOLDOWN`，默认 30 秒，应大于最大回包延迟）不再分配；
  因此相同 `IP:端口` 重建的新会话也不可能收到旧会话迟到的回包。
- **切换可靠性**：切换先写 SQLite 再生效，保存失败保留原目标并在网页报错。
- **重启**：目标接收器保存在 SQLite（`proxy-data` 卷）重启后保留；
  会话全在内存，重启即清空。

## 网页功能

- **切换目标接收器**：一键切换 A/B。
- **端口池演示**：让独立演示进程（代理在同一网络命名空间/容器内启动的子进程）
  真实占用或释放所选池内端口，并实时查看池状态（占用/冷却/预留）。
  占用连续 8 个端口后再发试传，可看到代理跳过被占端口绑定后面的空位；
  全部占满再发试传，可看到"端口池用尽"的建连失败原因。
- **发送试传**：携带试传标识的真实 UDP 报文经完整代理路径发往当前接收器；
  接收器按标识回报实收报文的 UDP 源端口，代理对照本次绑定端口。
  页面显示两端端口与核对结果：
  - **通过**：本次回执到达且两端端口一致；
  - **建连失败**：显示具体原因（端口池用尽 / 地址解析失败等）；
  - **未确认**：等待超时仍等不到本次回执；
  - **不符**：两端端口不一致。
  支持并行多条试传（各用各的回执，已结束试传的回执不再参与核对）。
- **活动会话 / 报文日志**：实时查看每个会话固定的接收器、每条报文的
  实际去向与回包（每 2 秒自动刷新）。

## 接收器

- 环境变量 `REPLY_DELAY`：该接收器所有回包的默认延迟秒数。
- 报文级覆盖：报文以 `DELAY:<秒>:` 开头时按该值延迟（回包仍是完整原始报文）。
- 试传报文 `UDPTRIAL1:<id>:<载荷>`：立即回执 `UDPTRIAL1:<id>:SEEN:<实收源端口>`。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `UDP_LISTEN_PORT` | `9000` | 代理对终端的 UDP 监听端口 |
| `HTTP_PORT` | `8080` | 操作网页端口 |
| `SESSION_IDLE_TIMEOUT` | `5` | 会话空闲超时（秒） |
| `RECEIVER_A_HOST/PORT`、`RECEIVER_B_HOST/PORT` | 见 compose | 接收器地址 |
| `DB_PATH` | `/data/proxy.db` | SQLite 路径（目标持久化） |
| `UPSTREAM_PORT_MIN/MAX` | `20000/29999` | 上游本地端口池 |
| `UPSTREAM_PORT_COOLDOWN` | `30` | 上游端口关闭后的冷却秒数 |
| `OPEN_SEARCH_TIMEOUT` | `15` | 一轮建连搜索端口池的最长耗时（秒） |

## 本地验证（无需 Docker）

```bash
pip install flask
python3 scripts/verify_local.py
```

逐项验证：原样透传（含二进制）；同机进程占住连续 8 个池内端口时新会话
仍绑定空位；试传两端端口一致判通过；池占满时建连失败报"端口池用尽"且
已有会话照常收发；外部释放端口后新会话无需重启即可使用；并行试传各用
各的回执且端口互不相同；切换后旧会话走原接收器；迟到回包不投递；
等不到回执显示未确认；地址解析失败单独上报；重启保留目标并清空会话；
保存失败保留原目标；以及端口分配器/试传核对的单元行为。
